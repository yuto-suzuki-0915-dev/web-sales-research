# Value Gap探索

モード: Value Gap。入力: $ARGUMENTS

このSkillは親セッションで実行する。`schemas/research-workflow.md` を読み、まず親がrunを保存・再読してから調査を `research-worker` に委任する。親自身はWeb検索しない。workerには以下の方針と今回の小バッチ上限を渡し、`schemas/research-handoff.md` の形式で返却させ、親がleadと台帳を保存する。

## worker向けモード方針

1. サービス・価格帯・比較検討の内容・メニュー・スタッフ等の事業情報、Mapsの口コミ、SNS活動、予約媒体や紹介に関する公開発信を入口にする。サイトのない事業者の収集から始めない。
2. 既存接点を確認する。口コミ数/評価・フォロワー数は媒体と確認日時を付けた観測値であり、流入数、売上、稼働率、将来LTVの代用にはしない。
3. 購入前に必要になりそうな情報と、その事業者に固有の理由を整理する。高単価業種という一般論だけでは有望にしない。
4. その後で公式サイトと既存チャネルを確認する。検索で見つからなければ「確認範囲で公式サイト未発見」。名称・所在地・公式SNS/Mapsのリンク等の確認範囲を残す。
5. Maps、SNSの固定投稿/プロフィール、予約媒体だけで情報確認から予約まで十分でないかを調べる。ページ数や独自ドメインの有無より、役割が満たされているかを見る。
6. 不足が残る場合だけ、情報整理、紹介後の信用確認、プラン比較、法人向け説明などサイトの役割を1〜3個に絞る。既存媒体の整備と比較する。

「SNSから客が来ている」はアクセス実績等の裏付けがなければ推測。接点の存在 → 情報不足の観測 → 受け皿の役割仮説、を分ける。workerは選別済みの保存用データを親へ返す。親は保存後、ユーザーに短い要約と保存先のみ伝える。
