# worker → 親の返却契約

workerはファイルを書かず、以下の保存用データを最終テキストで返す。親は検証してMarkdown正本へ反映する。この文書は返却形式であり、新しい保存先は増やさない。

## 量と完全性

- 初期確認は1〜3社、1社あたり約1,500文字以内を目安にする。詳細監査は1社、約6,000文字以内。証拠の欠落を招く切り詰めはせず、対象数を減らす/未完を明示する。
- 新規はleadテンプレートの必須情報を返す。既存は変更箇所・追加証拠・判定変更だけ返し、変化のない本文や人間のメモを再掲しない。既存証拠IDを使い回さない。
- 初期除外/保留も理由と根拠を返す。全件を「詳細はファイル参照」で済ませない。まだ保存していないファイルのパスを成果物として返さない。
- 生の検索結果、ページ全文、長い引用、思考過程は返さない。事実・推測・不明の区別を保った短い記録にする。

## 返却形式

### バッチ
- run-id / mode / phase:
- 返却状態: complete / partial / blocked
- 今回使った検索クエリ数と検索語:
- 確認した対象ID一覧 / 未着手の対象または範囲:
- 取得制約・未完理由・次に確認すること:

### 対象ごとの記録（初期確認最大3件、詳細監査1件）
- 操作: 新規 / 更新 / 再利用
- lead-id案、既存leadのパス（あれば）:
- 同定: 名称、別名、対象単位、所在地、業種、公式性の根拠、関連企業/店舗:
- 実施: 公開ページの取得試行の有無、初期確認/詳細監査/既存再利用、実確認日:
- 分類と判定: Demand/Redesign/Value Gap/未確定、有望/保留/除外、1〜3文の理由:
- 営業アクション: 営業候補 / 追加確認 / 見送り寄り / 営業対象外:
- 提案タイプ: 第一候補1つ、具体的内容、必要なら代替候補（選択肢と基準はresearch-guide参照）:
- 営業アクションの理由: F/I/U参照:
- 次に確認すること: 重要な1〜数点・方法・U-ID、低優先/不要ならその旨:
- 最小改善案: 現状維持/自己修正も比較し、保留でも条件付きで可:
- サイト改善不要という反対仮説: 支持材料と未確認点、F/I/U参照:
- 出典 Sxxx: URL、媒体/公式性、確認日時、公開/イベント日、取得方法/状態/範囲:
- 観測事実 Fxxx: 確認した内容と範囲 → Sxxx:
- 推測 Ixxx: 仮説 → Fxxx、成立/反証条件:
- 不明 Uxxx: 内容、理由、判定への影響、次の確認方法:
- 反対仮説: 実際の確認先、支持/反対材料、未確認点（初期未監査ならその旨）:
- 再調査条件/見直し目安:
- 更新時のみ: 旧判定→新判定、変更した項目、旧証拠の過去情報への変更と追加証拠ID:

### 詳細監査で必須の追記
- 事業・サービス・顧客・公開価格・スタッフ/拠点: F/I/U参照。
- Maps/口コミ、SNS、予約媒体、サイト、採用など各チャネル: F/I/U参照。非該当/取得不能を区別。
- 公開リンクの導線と、想定される流入/意思決定の導線: FとIを分離。
- 問題/機会と事業価値: F/I/U参照。
- 現状維持・媒体整備・小改修・新規制作・全面刷新の比較、更新/移行負担。
- G1〜G5それぞれの結果と根拠。最大の反証・不確実性。
- 有望時の営業理由。最小改善案・次の確認・反対仮説は調査判定を問わず上の共通欄に含める。

既存再利用も、leadパス・同定・過去の確認日・今回判定と正本判定の違い・根拠ID・再利用理由・再調査条件に加え、営業アクション/提案タイプ/理由/次の確認/最小改善案/反対仮説を返す。旧leadで未記載なら既存証拠から付与し、Web再取得なしと明記する。既に親が保存済みの初期確認を詳細監査した場合は「更新」で返し、2社に数えない。
