## 判定方法

現行版と改修版に同じ観察・出典・送信先情報を渡し、判定と根拠を照合する。提案の芯の「現在との差」がEvidenceと既存手段の調査に戻れるか、顧客心理や成果を創作していないか、文面が4つの失敗型に当たらないかを見る。正しいラベルでも理由が違えば不合格。確認できない点を「ない」と断定した結果も、妥当な小規模改善・Growth提案まで一律に見送る結果も不合格。

## 判定理由を固定する対照ケース

以下は利用者の観察を固定入力にした期待方向。店舗の現状や送信可否の確定ではない。`pursue`方向の例も、表中の差が確認できなければ文面生成へ進めない。

| 型・ケース | 期待方向と必要な理由 | 不合格となる理由 |
|---|---|---|
| DROP・SIFTERS | スタッフ作品から担当者比較・予約が既存媒体で可能なら、公式サイトへの作品転載だけでは役割差がない | 「公式サイトにも一覧を作れる」だけで通す |
| DROP・LoKaHi | 主要な説明・予約が既存サイトと外部予約で実現済みなら、同じ入口の再制作を撤回 | 直近更新や既存予約を見落とす |
| 宛先不一致・BIGOUDI武庫之荘 | 店舗サイトと指名予約が既にあり、採用用途のDMには店舗サイトの提案を送らない | 宛先だけ公式ならよいとみなす |
| WATCH・ヘアーサロン・アンジュ | トップ画像だけでは現在のスマホ導線と下層の反証が足りない。確認する画面・挙動を指定し文面なし | P3や婉曲表現で完成UIを決め打ちする |
| 弱い問題でDROP・エステサロンCoeur | 保存済み根拠では営業時間差が中心で、単発修正以上の役割差を説明できない | 安心感・予約率・管理負担を創作する |
| 小規模改善・Dearly Nail | `design → course/price → LINE`の接続に、既存媒体では果たしていない役割が実際にあれば限定提案を残す | 情報が別媒体にあるだけで通す、または小規模だから落とす |
| 小規模改善・PACT HOMIE | マンツーマンの店舗体験を伝える公式入口に、既存のSNS・予約先と異なる役割が確認できれば残す | 店舗の雰囲気だけから顧客の不安を創作する |

| Growth・Rebloom | BeautyとPilatesを横断して案内する公式ハブに、現行の各媒体と異なる役割が確認できれば残す | 媒体が分かれているだけで不足と断定する |

## 未使用ケースによる一般化確認

改修に使わなかった2〜3件を最後に読み取り専用で評価する。店名・URL・lead_idなどの識別情報だけを隠し、業種、サービス、媒体、観察事実、出典の種類、確認範囲・日時、証拠の質、連絡可能性は保持する。判定だけでなく、各差分の根拠と、文面を作る／止める理由を記録する。既知ケースでの調整後に結果を見て、店舗名の暗記や「全件見送り」への偏りを点検する。実際のrunの判定・文面・キューは検証で書き換えない。

固定ケースの合否と、現在のWebを再確認した送信判断は別に記録する。文例の語尾は採点せず、反証・役割差・根拠の確度・提案範囲・宛先を評価する。
